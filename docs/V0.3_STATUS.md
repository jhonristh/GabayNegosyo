## Decisions where I departed from a literal reading of the brief

1. **K14**: chose `tsc --noEmit` as the `lint` script over standing up a
   full ESLint flat config. A working type check catches most real bugs in
   a codebase this size; a full ESLint setup (rules selection, React
   Hooks plugin, a11y plugin) is a bigger, separate task I judged lower
   value than the rest of Phase 1 given the time available. This is a
   partial fix, flagged honestly rather than presented as the complete
   K14 resolution.
2. **`ContentStatus`**: built as a *computed* value (`lib/contentHealth.ts`)
   rather than a new hand-set field on every requirement/resource/tutorial.
   Setting `contentStatus: "verified" | "review_required" | ...` by hand on
   27 requirements would mean me making an editorial judgment call with no
   real authority behind it — exactly the kind of invention R2 rules out.
   Deriving it from `contentSource` + deadline-approximation language in
   the text keeps the signal honest and traceable to something the source
   material actually said.
3. **`--solid-border` contrast fix**: applied uniformly (0.12 → 0.5 alpha)
   rather than only to interactive-element borders. WCAG 1.4.11 most
   clearly requires this for operable UI boundaries (inputs, buttons); its
   application to purely decorative card dividers is more debatable. Fixed
   both the same way for simplicity and because I can't visually verify a
   split treatment would look right either. Flagged in "known risks" above.

- **K3 (real, serious bug, now fixed)**: the previous `public/sw.js`
  precached authenticated routes (`/dashboard`, `/account`, `/deadlines`,
  `/resources`) into an unscoped shared cache, and its fetch handler cached
  *every* GET response including cross-origin Supabase calls, falling back
  to cache on any network failure, not only true offline. On a shared

  `lib/auth.tsx`, so nothing from a session survives past sign-out on a
  shared device. Added `app/offline/page.tsx` (the fallback needs
  somewhere to point). Locked the real security property down with three
  new tests in `tests/pwa.test.js` (never precaches authenticated routes,
  bypasses cross-origin/`/api/`/`Authorization`-bearing requests).
- **K4/K5/L6**: `public/robots.txt` replaced with `app/robots.ts`

  cookieless page analytics — the client rule's actual requirement), wired
  `<Analytics />` into the root layout, and built `lib/webAnalytics.ts` for
  the five named conversion events. Kept this deliberately separate from
  the pre-existing `lib/analytics.ts`, which is a different, legitimate

- **B2 (real gap, now fixed)**: `/api/send-email` had no rate limit at all,
  and the *client* wrote its own `sent_emails` log row after a successful
  send — meaning a modified client could skip that write and send
  unlimited reminder emails with no server-side record or limit. Moved the
  log-write into the route itself (using the caller's own token, so the
  existing "insert own" RLS policy applies unchanged) and added a real
  per-user rate limit (5/hour) enforced by counting the caller's own rows
  before sending — a check that cannot be bypassed by client-side changes,
  since it runs entirely server-side against the caller's authenticated
  identity. Removed the now-dead `db.appendSentEmail()` (nothing calls it
  anymore) and replaced it with `db.refreshSentEmails()`, which just re-
  reads the log after a send instead of writing to it a second time. Two
  new tests lock in both halves of this (rate limit present, client no
  longer double-logs).
- **B1**: added `database/migrations/001_sent_emails_sent_at_index.sql` —
  the admin log's `order by sent_at desc limit N` query had no supporting

## Phase 2 (continued) — B2/B5 security headers + CSP

- **B2/B5 (real gap, now fixed)**: `next.config.js` had no security headers
  at all. Added a Content-Security-Policy plus `X-Content-Type-Options`,
  `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, and

  sourced" copy from the earlier round) under the new CSP, so it isn't
  silently blocking the app's own scripts/styles.
  - **Documented limitation, not hidden**: this is a same-origin-first CSP
    with `'unsafe-inline'` on `style-src` (Next's App Router injects some
    inline styles) and an explicit `connect-src` allowlist (Supabase,
    Vercel Analytics, Resend) — not a nonce-based `strict-dynamic` policy.
    A nonce-based CSP needs per-request middleware threading a nonce into
    every script tag, a bigger separate change not done this pass; said so
    directly in the config file's own comment rather than presenting this
    as the strongest possible CSP.
  - One new test locks in that all six headers and `frame-ancestors 'none'`
    are present in the config.
