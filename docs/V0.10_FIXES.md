## Tests
`tests/engine.real.test.js` imports the real `lib/ruleEngine.ts` and `lib/penalty.ts`. The older tests mirror logic inline and can pass while the app is wrong (e.g. `simulator.test.js` validated input the page never validated). 4 of the 8 new tests fail on the previous code.

## Not changed on purpose — needs a client / product decision
1. **"Overdue" is still unreachable.** Many requirement dates are documented approximate anchors ("Before starting operations" = Jan 1; monthly items = Dec 31). Rolling past dates forward is the only behaviour that never shows a false "overdue". Making overdue real needs a per-requirement recurrence field (`one_time` / `annual` / `monthly` / `quarterly`) in the content data, which is client content.
2. **Completion never resets for the next cycle.** Same root cause as (1).
3. Content data, eligibility rules, RLS/SQL and the client PDFs' conflicting PhilHealth / BIR-threshold figures were not touched.
